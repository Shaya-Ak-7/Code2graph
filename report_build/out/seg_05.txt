  for each BROKEN record b:
      if every missing node of b exists again in G:
          restore the original edge and mark b HEALED
      else if exactly one node in the same file and at the same
              location replaced it (rename):
          re-point the edge, restore it and mark b HEALED
  persist G to graph.json atomically, then notify the MCP server
Two properties of this algorithm deserve emphasis. First, only changed files are parsed again and unchanged nodes stay in the cached graph, so the cost of an update depends on the size of the change and not on the size of the repository. Second, healing is conservative: an edge is re-pointed only when a unique same-file, same-location match exists, because a missing edge is less harmful than a wrong one. Algorithm 4.2 is the core contribution of the mini project and it is the behaviour exercised in the experiment of Section 5.4.
4.6.3 GRAPH QUERY
Algorithm 4.3  QueryGraph(question, k, budget)
  terms  <- tokenise(question) minus stop words
  seeds  <- top-k nodes ranked by term overlap over label, id,
            source_file and rationale text
  context<- seeds
  for each node s in seeds:
      add the neighbours of s and their relations to context
  order the result by proximity to the seeds, then by score
  emit nodes and edges until `budget` tokens are consumed
The implementation additionally supports a depth-first mode for tracing a single path, an explicit context filter that restricts traversal to one class of edge (for example calls), and a token budget that truncates the answer while stating how many nodes were cut. The truncation message matters in practice: an agent that is told "26 of 268 nodes shown" can raise the budget or narrow the query instead of assuming the answer is complete.

4.8 TESTING STRATEGY
The repository follows the rule of one test file per module under tests. The suite is designed to avoid network access and uncontrolled file-system effects, and most tests are isolated with temporary directories and environment fixtures. The areas covered include extraction for every supported language, incremental rebuilds, MCP tools, broken-reference persistence, file deletion, symbol-rename healing and graph-cache reload behaviour. A special test, tests/test_architecture_doc.py, imports every symbol that is named in the architecture document, so the module table cannot drift away from the code. Two further guards protect generated artefacts: a generator check that fails if the committed agent-skill bundles differ from their source fragments, and a persistent-cache test that asserts an incremental rebuild produces the same graph as a cold build.

4.9 PACKAGING, CONTAINERS AND AUTOMATION
The project is packaged with pyproject.toml and uv.lock records the exact dependency versions. A Dockerfile and a .dockerignore file allow the tool to run in a container as a non-root user, and the Dockerfile documents the HTTP transport invocation. A pre-commit configuration runs the generated-artefact check and a linter before each commit, and the .github directory holds the continuous-integration workflow, which runs the suite on four Python versions and performs a static security scan and a dependency audit. The repository also ships a build-time generator for the agent instruction bundles: 134 generated artefacts are checked against their source fragments, so a hand edit to a generated file fails the check instead of silently diverging.
